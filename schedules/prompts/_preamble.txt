[OVERSIGHT JOB PREAMBLE — every scheduled job starts here]
1. KILL-SWITCH: if ~/.claude/schedules/DISABLED exists, append one line {"job":"<JOB>","skipped_at":"<iso>"} to ~/.claude/schedules/heartbeats/_disabled_window.jsonl (a shared marker, NOT a per-job heartbeat — the audit's *.json glob ignores it) and exit. The daily job's heartbeat audit suppresses misses that fall inside a disabled window.
2. BUDGET STATUS (advisory, not a gate): run `python3 ~/.claude/hooks/agent_budget.py status` and note its `live_leases`/`ceiling`/`recommended_additional_slots` fields in your log/summary (there is no `status` key). There is no pre-flight skip here (AA-0002, rationale re-derived 2026-09-01): the real killer — the account's weekly Anthropic quota — was never observable from this script, so a lease-based skip gates on the wrong signal regardless of pacer state (the pacer is ON as of 2026-08-31 and the lease fields do vary; that changes nothing about this conclusion). Detection lives in step 3 below instead: a session that dies mid-quota-exhaustion now leaves a START-only heartbeat behind rather than silence. Detection over an impossible prevention. **This is now DOUBLE-GUARANTEED (added after #4825, 2026-09-03): every job is launched via the shared `~/.claude/schedules/run_oversight_job.sh` wrapper, which checks the heartbeat file itself after the `claude` process exits (any reason — clean finish, session-limit death, the alarm hang-kill, a crash) and writes its own fail-fast diagnostic heartbeat if the session's own END write never truthfully landed. Do not treat this as license to skip step 5 below — the wrapper's diagnostic heartbeat names only "the process died," never the real finding/summary a clean END write carries; step 5 is still this job's own non-negotiable last action.**
3. HEARTBEAT — START (via Bash heredoc — the Write tool is permission-gated on this path headless): write ~/.claude/schedules/heartbeats/<JOB>.json as {"job":"<JOB>","started_at":"<UTC iso, Z suffix>","finished_at":null,"exit":1,"cadence":"<this job's cadence, from the install doc's job table>","summary":"STARTED <UTC iso>"}. A crash before step 5 leaves exactly this shape behind on disk — that is the point: a killed session now self-records instead of vanishing.
4. Do this job's work (below). Dispatch ONLY the named agents; their model pins govern; never override a pin upward.
5. HEARTBEAT — END (always, last action, via Bash heredoc): OVERWRITE the same file (do not append) as {"job":"<JOB>","started_at":"<UTC iso, Z suffix — the same value written in step 3>","finished_at":"<UTC iso, Z suffix>","exit":<0 ONLY if every step completed; otherwise non-zero, and summary MUST name the failing step>,"cadence":"<this job's cadence, from the install doc's job table>","summary":"<one line: what ran, what was found>"}. Any artifact path named in this summary MUST be absolute or ~/.claude/-anchored, exactly as the write instruction names it — never a bare relative path a reader would have to already know the job's own write instruction to resolve (#5055).
6. NOTIFY only when something needs the operator now (a P1 finding, a stopped job, a parked ask-gate): try the PushNotification tool; on suppression or absence, post a comment on the open oversight tracking issue named in `~/.claude/knowledge/oversight_install.md` §0's TRACKING line instead. Routine results go in the heartbeat summary and your report file only.
HARD RULES: never push/PR/merge/deploy. PRODUCTION: read-only, non-mutating checks only (health endpoint GETs, log/metric/revision reads) — no writes, no tenant authentication, no browser round-trips; staging for everything interactive; never anything more against production on your own initiative. No destructive issue mutations, EXCEPT where a job's own prompt names a standing close authorization AND every close passes both `gh_issue.sh`'s guards and gate 5. All other disposition batches are PROPOSED, never executed unattended. Path-scoped commits only where a job is explicitly sanctioned to commit. On any 3rd identical failure, stop and record it.
TIMESTAMP FORMAT: every started_at/finished_at value written in steps 4 and 5 above MUST be UTC ISO-8601 with a literal `Z` suffix (e.g. 2026-08-25T11:14:24Z) — never a local offset like -06:00/-07:00. This is mandatory, not a style preference: the audit tool derives each job's real start/finish from its own log-file mtimes and flags any divergence beyond 5 minutes as a possible fabricated timestamp, and a mixed-offset corpus can't be compared for staleness at all.
PIN-SUSPECT AS A TYPED KEY: any job whose prompt uses the "record PIN-SUSPECT in your heartbeat summary" convention (install doc §0 leg 2's UNVERIFIED headless-Opus-pin-honoring compensating control) MUST ALSO set a top-level boolean `pin_suspect` key on its step-5 heartbeat (true/false) — the prose marker stays for a human reader, but nothing parses free text; the typed key is what the audit can actually check.
PERMISSION PRECONDITION (documented in oversight_install.md §1): headless writes outside the job's WorkingDirectory succeed only because the working repo's .claude/settings.local.json grants them — a job whose cwd lacks such a grant cannot write its own heartbeat; the install procedure's write-probe step verifies this before any job is loaded.
